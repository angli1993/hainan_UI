# 0003 fMRI 特征边界与功能梯度

状态：Verified

## 背景

样板的“fMRI 特征提取”详情误将 ReHo 与静息态功能连接放在同一设置分组，容易让用户误以为功能连接会读取 ReHo 邻域和平滑参数。正式平台部署记录还表明已有独立的 `bold_gradients` 功能梯度，但样板未展示。

## 目标

- 将 ALFF/fALFF、ReHo、静息态功能连接和功能梯度作为四项独立结果展示。
- 明确 ReHo 邻域与结果图平滑只属于 ReHo。
- 功能连接单独选择图谱，并固定展示 Pearson 相关与 Fisher z 结果契约。
- 功能梯度单独选择平台图谱，形成独立配置与结果身份。
- 本次方案直接显示所选图谱的目录名称，并用具体计算起点替代抽象的“运行原则”。

## 非目标

- 不修改正式前端、后端、API、数据库或任务调度。
- 不在样板中新增尚未从本地代码核实的梯度维数、稀疏度或对齐参数。
- 不把功能梯度恢复为已撤回的 RISE 功能梯度实现。

## 设计

fMRI 结果列表增加“功能梯度”卡片。功能梯度与功能连接可以共享同一条合格的去噪时间序列，但各自保存图谱选择、特征配置和输出。特征阶段详情拆成四个区块，避免任何跨指标参数归属歧义。

本次方案中的图谱配置显示实际目录名称，例如 `BN_MNI152NLin2009cAsym_2mm`；选择多个图谱时逐项列出。原“运行原则”改为“计算起点”，按模态说明本次计算从哪类已有处理结果开始。

## 兼容影响

仅影响独立医生端样板。已有浏览器状态缺少功能梯度键时使用样板默认值，不影响其他特征选择。没有新增后端契约。

## 验收标准

- fMRI 结果列表包含四项独立特征。
- ReHo 与功能连接不再共享设置标题。
- 功能梯度展开后可从当前平台图谱库选择兼容图谱。
- 功能连接和功能梯度在未选图谱时均阻止确认方案。
- 本次方案显示实际图谱名称，不再只显示图谱数量；“计算起点”使用模态专属描述。
- 桌面、390 px 和 320 px 布局无横向溢出，交互与控制台无新增错误。

## 测试结果

- `npm test` 通过，生成页面与静态约束检查通过。
- 浏览器确认 fMRI 特征列表包含四项独立特征，阶段详情不再合并 ReHo 与功能连接。
- 功能梯度图谱弹窗仅显示当前任务空间兼容的 18 个图谱；清空图谱后应用会被阻止并显示明确提示。
- 浏览器确认本次方案显示实际图谱目录名 `BN_MNI152NLin2009cAsym_2mm`，并将计算起点明确为“从已完成的静息态 fMRI 去噪结果开始”；长名称在方案栏内正常换行。
- 1280 px 桌面视口无页面或特征卡横向溢出；新增内容复用此前已验证的 390 px 与 320 px 响应式卡片和纵向详情布局。

## 风险和回滚

本地正式项目分支未包含服务器上的 0086 功能梯度源码，因此样板只表达已确认的产品边界，不展示未核实的高级参数。回滚时撤销本变更即可，不影响正式平台。
