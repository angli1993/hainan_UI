# 0005 fMRI 特征方案与缓存复用

状态：Verified

## 背景

现有样板把“静息态 fMRI 去噪”显示为一套全局配置，并在本次方案中固定写成“从已完成的静息态 fMRI 去噪结果开始”。这会误导使用者认为 ALFF/fALFF、ReHo、功能连接和功能梯度总是读取同一个后处理时间序列，也无法表达已有兼容结果应被复用、只有分叉后的步骤才重新计算。

## 目标

- 选择 fMRI 特征时加载该特征的推荐处理方案。
- 医生端保持简洁，同时允许展开查看处理路径和调整允许修改的参数。
- 用确定性规则展示最近可复用节点、复用检查数和新增计算数。
- 参数变化实时更新复用方案；只影响分叉后的步骤，不无条件重跑 BIDS 转换或预处理。
- 明确功能梯度可以复用兼容的脑区时间序列或连接中间产物，但不要求先发布功能连接结果。
- 形成可推广到 T1、DWI 和 EEG 的“配方编译 + 缓存查询”界面模式。

## 非目标

- 不修改正式项目、后端、API、数据库或任务调度。
- 不实现真实缓存查询、影像计算或 Agent/LLM 决策。
- 本次不把同一模式扩展到 T1、DWI 或 EEG。
- 不增加 Degree Centrality。

## 设计

### 页面结构

fMRI 保留四个顶层阶段：

```text
BIDS 数据 -> fMRI 预处理 -> 时间序列处理 -> fMRI 特征提取
```

第三阶段是特征方案中的时间序列处理集合，不代表一份供全部特征共用的全局去噪文件。每个特征卡显示推荐方案状态、结果形式、图谱要求，并提供“查看处理路径”和“调整参数”入口。

### 缓存匹配

正式系统应由确定性代码根据下列身份字段计算工件键并逐层查找缓存：

```text
患者/随访 + 输入工件摘要 + 预处理版本及参数 + 容器摘要
+ 时间序列参数 + 输出空间 + 图谱及版本 + 特征参数及版本
```

前端只展示后端返回的匹配结论，不自行判断真实任务兼容性。本样板用合成规则演示三种情况：

1. 已做功能连接后选择 ReHo，从兼容的预处理 BOLD 开始。
2. 只修改 ReHo 邻域时复用时间序列，只重算 ReHo。
3. 功能连接和功能梯度的图谱及相关参数相同时，共享兼容的脑区时间序列/连接中间产物。

### 样板数据

- 128 位患者，196 次检查。
- 172 次检查具备可用 BIDS 数据。
- 146 次检查已有兼容的 fMRI 预处理结果。
- 默认选择 ReHo：98 次兼容时间序列结果可复用，48 次需要时间序列处理，146 次需要 ReHo 计算。

## 兼容影响

- 保留 Agent 工作台、量表、患者、字段字典、导入历史、其他影像模态和平台图谱库页面。
- 仅改变 fMRI 样板的术语、状态和交互；不改变任何正式接口。
- 浏览器中旧版 fMRI 设置会与新默认字段合并；不识别的旧字段不参与新方案展示。

## 验收标准

- 默认进入 fMRI 页面时可清楚看到 ReHo 推荐方案和最近可复用节点。
- ReHo 处理路径按 BIDS、预处理 BOLD、ReHo 时间序列处理、ReHo 计算显示复用/新增状态。
- 修改 ReHo 邻域后，时间序列复用数不变，ReHo 计算标为参数已调整。
- 修改时间滤波后，复用数和新增时间序列处理数同步变化。
- 功能连接和功能梯度选择相同图谱时显示共享兼容中间产物；图谱不同时不显示共享。
- 每张 fMRI 特征卡均可单独查看路径与调整参数。
- 页面在桌面、390 px 和 320 px 下无文字遮挡、横向溢出或控制失效，控制台无错误。
- `npm test` 与 `git diff --check` 通过。

## 测试结果

- `npm test` 通过，生成页与源片段一致，静态契约检查通过。
- `git diff --check` 通过。
- Playwright 使用本机 Microsoft Edge 验证 1440、390 和 320 px：无横向溢出，控制台无错误。
- 浏览器交互验证：ReHo 默认复用 98 次时间序列；只改邻域仍复用 98 次；时间滤波改为 0.01–0.1 Hz 后复用 32 次并新增 114 次时间序列处理。
- 浏览器交互验证：功能连接和功能梯度使用相同默认图谱、时间序列方案时，页面显示共享兼容中间产物且结果独立保存。
- 验证同步 CDN 图标脚本改为延迟加载，网络不可用时不再阻塞页面主体解析。

## 风险和回滚

- 样板计数是合成数据，必须持续标注为演示，不能被理解为真实任务状态。
- 推荐方案只表达产品契约，不证明具体算法或参数已经经过科研验证。
- 可回滚到提交 `32f207e`，恢复上一版模态管线与图谱工作台。
