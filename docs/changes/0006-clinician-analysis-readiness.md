# 0006 医生端分析准备度与任务衔接

状态：Verified

## 背景

fMRI 页面已经能够表达推荐方案、参数调整和缓存复用，但“本次方案”仍优先展示预处理 BOLD、复用节点和新增计算作业等工程信息。医生完成指标选择后只能看到“确认方案与数据范围”，无法直观判断多少检查可以分析、多少需要补处理、多少暂时不能纳入，以及确认之后会发生什么。

## 目标

- 主视图优先回答可分析数量、可直接计算数量、需补充 BOLD 去噪数量和暂不可分析数量。
- 将缓存节点、关键参数和计算作业下沉到可展开的技术方案。
- 区分“队列推荐方案 v1.0”和“自定义草案”，避免不同参数结果被误认为同一方案。
- 增加分析前检查，解释本次纳入范围、未纳入原因和后续任务流程。
- 保留特征级推荐配方、参数调整、图谱选择和缓存复用逻辑。

## 非目标

- 不创建真实分析任务，不连接后端、数据库或任务队列。
- 不实现真实质量控制、失败重试或结果页面。
- 不改变 DWI、T1、EEG 和平台图谱库的业务契约。
- 不允许 Agent/LLM 决定检查是否纳入分析。

## 设计

### 本次方案

医生默认看到：

```text
分析范围
所选指标
方案版本
可分析检查
可直接计算 / 需补充 BOLD 去噪 / 暂不可分析
```

技术方案折叠显示处理来源、最深兼容节点、关键参数和新增作业数。去噪作业与特征计算使用不同统计行，不把不同处理层级写成相加口径。

### 分析前检查

样板使用合成数据展示：

- 172 次检查具有可用 BIDS 数据。
- 146 次检查可进入本次 ReHo 分析。
- 推荐方案下 98 次可直接计算，48 次需补充 BOLD 去噪。
- 26 次暂不可分析：18 次等待预处理，5 次等待影像质控，3 次缺少完整 BOLD/T1w 关联。

检查页同时展示后续阶段：创建任务、补充 BOLD 去噪、人工质控、查看结果。

### 方案版本

全部指标使用默认参数时显示“队列推荐方案 v1.0”。任一指标参数变化后显示“自定义草案”，并提示正式系统应创建新方案版本，不能自动与推荐方案结果合并。

## 兼容影响

- 只改变 fMRI 样板的信息层级和确认交互。
- 原有技术信息仍然保留，但默认折叠。
- 样板数字继续明确标注为演示数据，不代表真实任务状态。

## 验收标准

- 默认 ReHo 页面首先显示 146 次可分析、98 次可直接计算、48 次需补充 BOLD 去噪、26 次暂不可分析。
- 技术方案默认折叠，展开后仍能看到复用节点、关键参数和计算数量。
- 修改 ReHo 参数后方案状态显示“自定义草案”。
- “检查数据并继续”打开分析前检查，列出纳入范围和 26 次未纳入原因。
- 分析前检查展示创建任务、补充 BOLD 去噪、人工质控和查看结果的后续流程。
- 页面明确说明样板不会创建真实任务。
- 桌面、390 px 和 320 px 无横向溢出、文字遮挡和控制台错误。
- `npm test` 与 `git diff --check` 通过。

## 测试结果

- `npm test` 通过，生成页与源片段一致，静态产品契约检查通过。
- `git diff --check` 通过。
- Playwright 使用本机 Microsoft Edge 验证 1440、390 和 320 px：默认准备度数字、技术方案展开均正确，无横向溢出和控制台错误。
- 分析前检查验证通过：3 类未纳入原因、4 个后续阶段和样板任务提示均可交互。
- 修改 ReHo 邻域后，指标卡与本次方案均显示“自定义草案”。
- 320 px 弹窗从当前视口打开，内容在弹窗内部滚动，摘要行不再压缩，底部操作保持可见。
- 功能连接示例显示 112 次可直接计算、34 次需补充 BOLD 去噪、26 次暂不可分析；技术方案将 34 次 BOLD 去噪与 146 次连接矩阵生成分行呈现，不再使用相加口径。
- 浏览器验证 1280、390 和 320 px 均无横向溢出；320 px 的准备度指标与技术方案内容保持在方案面板内，控制台无警告或错误。

## 风险和回滚

- 准备度计数为合成数据，正式系统必须由确定性后端聚合，不由前端计算。
- “可分析”只表示满足输入与处理条件，不表示具有临床诊断意义。
- 可回滚到提交 `8f30928`，恢复技术方案优先的上一版 fMRI 页面。
