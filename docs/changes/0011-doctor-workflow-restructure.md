# 0011 医生端信息架构重组：Agent 工作台、数据管理、特征库与模型

状态：Implemented

## 背景

0010 完成视觉系统升级后，产品方提出医生端的工作方式应当围绕"上传与管理数据 → 预处理 → 在特征库中生成特征 → 用 Agent 做科研探索 → 用模型形成个体报告"展开。原型中的 Agent 工作台同时承担上传与对话，模态页面把阶段、结果选择与方案摘要挤在一页，保留页面没有任何演示内容，医生第一次打开难以理解。

本变更同时参考了近期智能体研究中的几个可借鉴设计：本地部署与版本固定（Zhang et al., *Nature Medicine* 2026；Ferber et al., *Nature* 2026）、以重复运行一致性作为可靠性信号并对低一致性结果转人工复核（选择性自主）、每个输出附带推理轨迹与工具记录、智能体先筛与多级质控（NeuroPilot）、生成-执行-校验循环与仅在边缘案例升级人工（NeuroAgent）、批评者智能体与阶段性人工检查点（Virtual Lab、AI co-scientist）。

## 目标

- 重组导航：Agent 工作台（交互式科研挖掘、自动科研智能体）、数据管理（数据上传、数据总览、样本随访、字段字典、导入历史）、神经影像（影像数据总览、fMRI 功能像、DWI 弥散像、T1 结构像、特征库、图谱库）、神经电生理（电生理数据总览、静息态 EEG）、体检报告、模型（第三方模型、私有模型）。
- 医生端统一使用"样本"代替"患者"，覆盖病例与健康志愿者。
- 数据上传从对话中分离，按类型选择并记录上传者与权限；对话只负责查询与分析。
- 模态页面改为"队列选择 → 四节点流程（BIDS 标准化、预处理、质控、特征提取）"，一次只展开一个节点；预处理在页面内选择 fMRIPrep / DeepPrep；质控采用"智能体先筛，医生确认"。
- 新增跨模态特征库（Gallery）：特征卡片、详情抽屉（用途、参数、图谱、先决条件、处理路径、参考文献、预计时间）、批量计算与计算前检查、运行进度模拟。
- 图谱库新增"图谱方案"（皮层 + 皮下 + 小脑）：功能方案（Schaefer 200 + Tian + SUIT）、脑网络组方案（BN 210 + BN 皮下 + BN 小脑）、自定义方案；全局默认，单特征可覆盖。
- 自动科研智能体：任务（数据范围、模态、模型、频率、边界）、汇报时间线、发现级一致性评分与"可采纳 / 待复核"门控、批评者复核、与交互式挖掘互通。
- 保留页面填充合成演示数据：数据总览（指标、图表、队列、最近导入、算力）、30 个样本的随访与量表、约 40 个字段、12 条导入记录。
- 模型页按第三方 / 私有分开；私有模型可"发布给合作者"并选择授权范围。
- 每个页面带可关闭的引导卡与术语悬停解释；侧栏底部显示本地算力与任务状态。

## 非目标

- 不接入真实后端；所有计算进度、报告、模型结果均为合成演示。
- 不实现语音识别；语音按钮仅演示状态。
- 不改变既有缓存复用、准备度、图谱契约与模型契约的计算逻辑（相关函数原样保留并继续被阶段详情、处理路径与计算前检查复用）。

## 设计

### 页面与状态

```text
Agent 工作台
  ├─ 交互式科研挖掘  chat    可用数据摘要 · 结果卡（表格、图、过程记录、一致性）· 引用数据 · 语音
  └─ 自动科研智能体  auto    任务卡 · 任务详情 · 汇报时间线 · 汇报抽屉 · 添加任务弹窗
数据管理
  ├─ 数据上传        upload  类型卡 → 表单 → 流程说明；表格类型复用字段映射弹窗
  ├─ 数据总览        dashboard
  ├─ 样本随访        samples 列表 + 详情（随访、量表、影像、质控）
  ├─ 字段字典        catalog 分类 + 表格 + 搜索
  └─ 导入历史        history 列表 + 详情
神经影像
  ├─ 影像数据总览    imaging-overview
  ├─ fMRI / DWI / T1 fmri, dwi, t1   队列 → 节点轨道 → 节点面板（stageOpen）
  ├─ 特征库          features  featureSel / featureRuns / featureFilter / 抽屉 / 计算前检查
  └─ 图谱库          atlases   scheme / customScheme + 既有图谱目录与查看器
神经电生理           ephys-overview, eeg（接口待接入）
体检报告             report（复用个体综合评估，改为"样本"口径）
模型                 models-external, models-private（研究方案设计作为私有模型的动作）
```

新增状态保存在 `localStorage['hainan-ui-v3']`（队列、已选特征、图谱方案）与 `localStorage['hainan-ui-guides']`（已关闭的引导卡），与宿主 widget state 分离。

### 可靠性与边界（借鉴智能体研究）

- 自动任务默认"重复运行 5 次"，发现按一致次数显示 5 个圆点；达到门槛标"可采纳"，否则"待复核"。
- 每个结果卡带"过程记录"：特征工件、筛选条件、统计方法、批评者复核。
- 任务边界默认包含"只使用质控通过的数据""不生成诊断结论""结果需医生复核后采纳"。
- 页面显示本地模型名称与"数据不出院"。

### 静态检查

`scripts/check.mjs` 重写：校验新导航与关键文案、禁止"患者"、保留既有处理语义检查（去噪分离、缓存复用、DTI / T1 分支、默认图谱）、新增特征库 / 图谱方案 / 自动智能体的结构检查。

## 兼容影响

- 页面 id 变化：`workspace → chat`、`patients → samples`、`assessment → report`、`models → models-private`，旧 widget state 自动映射。
- 原 `imagingHtml`、`workspaceHtml`、`retainedHtml`、`modelCenterHtml` 不再使用；`atlasLibraryHtml`、阶段详情、图谱选择、分析前检查、字段映射等原样保留。
- 术语：全文"患者"改为"样本"（`docs/terminology.md` 同步）。

## 验收标准

- 18 个页面全部可渲染，控制台无错误；1440 px 与窄屏无横向溢出。
- 每个模态页只展开一个节点；预处理选择与高级参数联动；质控通过 / 退回可记录。
- 特征库勾选、详情、开始计算、计算前检查、模拟进度全部可操作。
- 图谱方案切换后特征库工具栏同步显示。
- 自动任务可添加；汇报可打开并跳转到交互式挖掘或研究方案设计。

## 测试结果

- `npm test` 通过。
- 本地 `npm run serve`，1440×900 逐页截图并通过脚本遍历 18 个页面，无运行时错误。

## 风险与回滚

- 风险：演示数据较多，正式接入时需要逐页替换为接口数据；特征参考文献与引用数为示意，需资源管理员核对。
- 回滚：`git checkout` 0010 版本的 `src/integrated-clinical-workbench.fragment.html` 与 `scripts/check.mjs` 后重新构建。
